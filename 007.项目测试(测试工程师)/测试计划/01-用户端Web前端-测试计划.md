## 1. 项目识别

### 1.1 技术栈

| 维度 | 内容 |
|---|---|
| 形态 | 零框架静态 HTML + Tailwind CSS（CDN），无构建 |
| 脚本分层 | 共享脚本 `assets/proto-nav.js`（跳转接线 + 客户端登录守卫 + `doLogout`）+ 各页内联 `<script>`（页面特有行为） |
| 数据来源 | 已接真库：分类/账户/账单/头像全部走后端 `/api/*`，**无内存演示残留** |
| 第三方 | SheetJS（CDN，仅 07 页「导出 .xlsx」演示）、Material Symbols（图标连字）、Chart.js（本地 `chart.umd.js`） |
| 运行依赖 | Tailwind CDN、字体图标需联网；后端同源托管（3000 端口） |

## 4. 分层测试方案

| 层 | 内容 | 工具/方式 | 覆盖目标 |
|---|---|---|---|
| L1 静态检查 | 页面结构、`data-page` 引用、内联脚本语法 | `node --check assets/proto-nav.js`、人工核对各页注入 | 11 页可正常加载、无脚本报错 |
| L2 前端逻辑单测 | 金额换算、日期步进、分页、`esc` 转义 | 浏览器 Console 手测 + 边界值表 | 高风险纯函数边界 |
| L3 接口联调 | 前端 fetch 与后端 `/api/*` 契约一致 | 走 :3000 后端，浏览器 Network 核对请求/响应 | 各页数据真实渲染 |
| L4 E2E 主流程 | 注册→记账→流水→统计→管理→退出 全链路 | 人工 + 建议引入 Playwright 快照 | 主流程闭环、跳转接线 |
| L5 兼容性 | 手机浏览器优先（Chrome/Safari/微信内置）、桌面窄窗口响应式 | 真机 + DevTools 移动模拟 | 布局/字号/安全区 |
| L6 非功能（前端侧） | 弱网/断网、Tailwind CDN 加载失败、双主题一致性 | 断网模拟 | 降级不白屏、错误提示友好 |

> 分层原则：前端重点在 L2–L4；接口正确性归后端测试计划，前端只验「接对字段、渲染正确、失败提示正确」。

## 7. 缺陷分级与出口准则

| 级别 | 定义 | 示例 |
|---|---|---|
| P0 致命 | 主流程阻断/数据错乱 | 金额换算错误、保存后数据丢失、越权 |

| P3 建议 | 优化 | 过渡动画、留白 |

**出口准则**：P0/P1 全部关闭；P2 关闭率 ≥ 90%；F1/F3/F4/F7 主流程 E2E 全绿；`node --check proto-nav.js` 无语法错误。

## 8. 风险与依赖

- 前端为「高保真原型 + 真库数据」混合态，存在 README 与当前实现不一致的**文档漂移**风险，测试以当前代码行为为准。
