## 一、部署架构总览

| 组件 | 来源目录 | 端口 | 说明 |
|---|---|---|---|
| 用户端后端（含 Web 前端静态托管） | `003.前端代码/backend` | 3000 | Express 5 + mysql2，同源托管 `../frontend`，默认首页=登录页 |
| 运营后台后端（含后台页面托管） | `005.后台管理系统(运营专员)/backend` | 3002 | 独立 Express，连同一 MySQL 库，仅 `/api/admin/*` |
| MySQL 8 | `004.数据库脚本(数据库管理员DBA)` | 3306 | 库名 `financial_steward`，utf8mb4 |
| nginx（反向代理，可选但推荐） | 服务器 `Desktop\nginx-1.30.6` | 80 | 统一入口：80 → 3000/3002 分流；HTTPS 终结点 |

```
浏览器 ──> :80 nginx ──┬── /api/admin/*、/pages/admin_*.html ──> :3002 运营后台
                      └── 其余全部（/、/pages/*、/api/*、/uploads/*）──> :3000 用户端
```

**两套后端零跨域设计**：各自前端与 API 同源部署，nginx 只做路径分流，后端无需开 CORS。

## 六、生产启动与常驻（Windows 计划任务）

> ⚠️ **本服务器最重要的坑**：Windows OpenSSH 的会话作业对象会在 SSH 断开时杀掉子进程——SSH 里 `start` / `Start-Process` 拉起的一切都活不过会话结束。**常驻进程只能用计划任务（schtasks）拉起**（`schtasks /Run` 或系统启动触发）。

为两套后端各建一个计划任务（管理员 cmd）：

```bat
schtasks /Create /TN "fgj-user-3000" /SC ONSTART /RU SYSTEM ^
  /TR "cmd /c cd /d D:\financial-steward\003-backend && node src\server.js >> D:\financial-steward\logs\user-3000.log 2>&1"

schtasks /Create /TN "fgj-admin-3002" /SC ONSTART /RU SYSTEM ^
  /TR "cmd /c cd /d D:\financial-steward\005-backend && node src\server.js >> D:\financial-steward\logs\admin-3002.log 2>&1"

mkdir D:\financial-steward\logs
schtasks /Run /TN "fgj-user-3000"
schtasks /Run /TN "fgj-admin-3002"
```

日常重启（发版后）同样用 `schtasks /Run`；停止用 `taskkill /F /IM node.exe`（注意会停掉全部 node，逐 PID 停更稳妥：`netstat -ano | findstr :3000` 找 PID 再 `taskkill /F /PID <pid>`）。

> 开发机本地不需要计划任务：`npm start`（nodemon 热重载）即可。

## 七、nginx 反向代理

`Desktop\nginx-1.30.6\conf\nginx.conf` 的 `http` 段内：

```nginx
server {
    listen 80;
    server_name _;

    # 头像 base64 上传放宽到 10MB（与后端 express.json limit 一致）
    client_max_body_size 10m;

    gzip on;
    gzip_types text/css application/javascript application/json image/svg+xml;

    # 运营后台：API 与页面都指向 3002
    location /api/admin/ { proxy_pass http://127.0.0.1:3002; }
    location /pages/admin_ { proxy_pass http://127.0.0.1:3002; }

    # 其余全部给用户端（页面 / 用户 API / 头像上传目录）
    location / { proxy_pass http://127.0.0.1:3000; }

    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
}
```

> `/pages/admin_` 前缀分流依赖后台页面命名（`admin_*.html`）；首次部署后务必逐页点验后台五个页面与用户端全部页面，确认没有串到另一个后端。

**nginx 的启动/重启纪律**（历史事故：裸 `start nginx` 叠出 18 个重复进程导致端口打架）：

```bat
schtasks /Run /TN nginx-autostart      :: 启动/重启（已存在的 ONSTART 计划任务，-p 前缀已配置）
taskkill /F /IM nginx.exe              :: 先停
:: 改完 conf 后：先 taskkill 再 schtasks /Run；绝不要双击 nginx.exe 或裸 start nginx
```

计划任务 `nginx-autostart` 的 `/TR` 必须带 `-p C:/Users/Administrator/Desktop/nginx-1.30.6/` 前缀（否则工作目录落在 System32 找不到配置直接退出），该任务已存在，勿重建。

4. 全站 http 明文流量清零后，用 `curl -I https://<域名>/` 验证证书与跳转。

## 九、数据备份

每日 02:00 计划任务导出全库（保留 14 天）：

```bat
schtasks /Create /TN "fgj-db-backup" /SC DAILY /ST 02:00 /RU SYSTEM ^
  /TR "cmd /c C:\mysql\mysql-winx64\bin\mysqldump -uroot -p<密码> financial_steward > D:\backup\fgj_%date:~0,4%%date:~5,2%%date:~8,2%.sql && forfiles /P D:\backup /M fgj_*.sql /D -14 /C \"cmd /c del @path\""
```

恢复：`mysql -uroot -p financial_steward < D:\backup\fgj_YYYYMMDD.sql`。备份目录同时拷贝一份到对象存储/另一台机器（单机备份不算备份）。

## 十、发版流程

1. 打新代码包上传解压（或 `git pull`），保持第四节目录结构；
2. 两后端目录若有依赖变更：`npm install --omit=dev`；
3. 有 SQL 变更（004 目录新增脚本）则先导入再重启后端；
4. 重启：`schtasks /Run /TN fgj-user-3000`、`fgj-admin-3002`（先 taskkill 旧进程，见第六节）；
5. 冒烟（全部应 200/预期状态码）：

```bat

curl http://localhost:3000/api/auth/captcha          :: 返回 captchaId JSON
curl -I http://localhost:3002/pages/admin_login.html
curl -I -X GET http://localhost:3002/api/admin/dashboard   :: 未登录应 401
```

## 十一、常见故障排查

| 症状 | 原因 | 处置 |
|---|---|---|
| 页面 502 | node 后端未起/崩溃 | 看 `logs\*-3000.log`；`netstat -ano | findstr :3000` 确认监听；`schtasks /Run` 重拉 |
| 后台页面能开、数据 404 | nginx 分流规则未生效/写错 | 检查 `/api/admin/` 与 `/pages/admin_` location；taskkill 后 schtasks 重启 nginx |
| SSH 里起的进程莫名消失 | OpenSSH 会话作业对象杀子进程 | 一律改用计划任务拉起（第六节） |
| nginx 起不来或行为怪 | 重复进程端口打架 / 丢了 `-p` | `taskkill /F /IM nginx.exe` 清干净再 `schtasks /Run /TN nginx-autostart` |
| 中文输出乱码（SSH） | 远端默认 GBK | PowerShell 前置 `[Console]::OutputEncoding=[Text.Encoding]::UTF8` |
| 登录一直「服务器开小差」 | MySQL 停了/密码错 | `net start MySQL`；核对两后端 `.env` |
| 找回密码验证码刷不出 | `/api/auth/captcha` 429（限流）或 nginx 分流漏配 | 等一分钟重试；检查 nginx 日志 |
