## 一、产品介绍

财务管家是一个用来记录日常收支的记账工具，定位很简单：**点开就能记，记完就能走**。

它不追求大而全，刻意不做预算、多账户余额、账单导入、理财导流这些重功能，只把一件事做好——让用户花几秒钟记完一笔账，月底能看清楚钱花在了哪、挣了多少。目标用户是三类人：想随手记账的上班族、替家庭统一记账的人，以及想简单记生意流水的小微个体户。

产品一共包含三个部分，面向不同的人：

- **Web 网页端**：手机浏览器打开就能用，不用下载安装，是用户记账的主要入口。
- **移动端 App**：同一套功能做成 App，支持 Android、iOS、微信小程序和鸿蒙系统，方便想固定用 App 记账的用户。
- **运营后台**：给运营管理人员用的电脑端系统，用来查看整体数据、用户情况、账单流水，并导出报表。

三个部分共用同一个数据库，用户在网页端和 App 上记的账是同一份数据，运营后台看到的就是这些数据的汇总。

## 二、用户角色

产品里只有两类角色，职责和入口互不相同，账号体系也完全隔离。

### 1. 记账用户

使用 Web 端或移动 App 的人。他们做的事是：

- 注册账号、登录、找回密码；
- 记录每一笔支出或收入；
- 查看账单流水和年度统计；
- 维护自己的分类和支付账户；
- 上传头像、退出登录、注销账号。

记账用户只能看到和操作自己的数据，看不到别人的账。

### 2. 运营管理员（超级管理员）

使用运营后台的人，通常是负责产品运营的工作人员。他们做的事是：

- 登录运营后台；
- 查看数据总览（用户数、账单数、收支汇总、近 30 天趋势）；
- 查看用户列表、搜索和查看单个用户的详情；
- 按条件筛选所有用户的账单，并汇总金额；
- 查看按年或近 12 个月的统计报表；
- 把用户列表、账单流水导出成 CSV 文件。

运营管理员只有查看权限，系统里的数据是只读的，不能修改或删除用户的账。

> 说明：账号封禁、账号注销、操作审计这三项功能，按当前版本规划属于后续阶段，本期默认不开放。

## 三、产品构成与访问方式

| 端 | 面向谁 | 怎么访问 | 运行端口 |
|---|---|---|---|
| Web 网页端 | 记账用户 | 浏览器打开地址，自动跳到登录页 | 3000 |
| 移动端 App | 记账用户 | App 安装包 / 微信小程序 / H5 | 连接 3000 后端 |
| 运营后台 | 运营管理员 | 电脑浏览器打开地址，自动跳到登录页 | 3002 |

### 1. Web 网页端

启动后端服务后，浏览器访问 `http://localhost:3000/`，会自动跳转到登录页。登录、注册、找回密码三页是公开的，其余页面未登录时会自动跳回登录页。

页面共 11 个，主流程顺序是：登录/注册 → 记一笔 → 流水 → 年度统计 → 我的 → 设置（退出与注销），另有账户管理、分类管理两张扩展页从「我的」进入。

### 2. 移动端 App

移动端是跨端项目，一套代码同时支持 H5、微信小程序、Android、iOS 和鸿蒙系统。App 底部有四个导航入口：**流水、记一笔、统计、我的**，中间的「记一笔」是悬浮圆形按钮，方便随时点开记账。

App 连接的后端接口和 Web 端完全相同，数据互通。

### 3. 运营后台

启动后台服务后，浏览器访问 `http://localhost:3002/`，会自动跳到管理员登录页。登录后进入桌面布局的仪表盘，左侧是导航菜单，顶部是标题栏，各页面用图表（柱状图、折线图、饼图）展示数据。

## 四、核心功能说明

### 4.1 用户端功能

#### （1）账号

- **注册**：设置用户名和密码即可，不需要填手机号或邮箱。新账号的分类和账户初始为空，由用户自己添加。
- **登录**：用户名加密码登录。密码连续输错 5 次，账号会锁定 10 分钟。
- **找回密码**：输入账号后直接重设新密码，流程简单。
- **退出登录**：结束本机登录，不会删除数据。
- **注销账号**：永久清空该账号的全部记账数据，操作前会弹出警告确认，并要求输入密码确认。

密码规则：6 位以上，且数字、小写字母、大写字母、特殊字符这四类里至少要包含三类。

#### （2）记一笔

这是产品的核心功能，也是打开后默认停留的页面。分「支出」和「收入」两个画面，颜色分别为樱花粉和薄荷绿。

记一笔需要三步：

1. 选分类（支出分类如餐饮、交通，收入分类如工资、营业款）；
2. 输入金额；
3. 选账户（也就是这笔钱从哪付、收到哪）、备注、日期，然后保存。

分类九宫格每页显示 6 个，超出自动分页。账户只是「支付方式」的标记（比如现金、支付宝、微信、银行卡），不涉及余额，更不是多账户体系。

#### （3）流水

按日期列出所有账单，能看到每一笔的分类、金额、账户和备注。支出金额显示为深灰色带「-」，收入显示为薄荷绿带「+」。点某一条账单可以查看详情，并进行编辑或删除。账单较多时分页加载。

#### （4）年度统计

按年查看自己的记账情况，包含四块内容：

- **记账概况**：这一年记了多少笔、月均支出多少、最大单笔是多少；
- **分类占比**：各分类占总支出或总收入的比例；
- **收支趋势**：全年收入和支出的变化趋势；
- **分类排行**：支出和收入各自的分类金额排行，可切换年份。

#### （5）账户管理

维护记账时可选择的支付账户（仅作标记，不含余额）。支持添加、编辑、删除，账户名称加图标（emoji）展示。常见账户如现金、支付宝、微信、银行卡。

#### （6）分类管理

分「支出分类」和「收入分类」两个标签页，支持添加、编辑、删除分类。分类由名称加图标（emoji）组成，名称最多 6 个汉字。这里维护的分类，会直接出现在「记一笔」的分类九宫格里。

#### （7）我的 / 设置

「我的」页展示用户昵称、头像、注册日期，以及「已坚持记账 N 天」的徽章，并提供头像上传、账户管理、分类管理、注销账号等入口。「设置」页提供退出登录和注销账号的操作。头像可以上传本地图片更换。

### 4.2 运营后台功能

运营后台共实现六块功能（编号 A1–A6），全部只读。

| 编号 | 功能 | 说明 |
|---|---|---|
| A1 | 登录 / 登出 | 超级管理员账号登录，会话独立存于管理员表，与用户账号隔离 |
| A2 | 数据总览 | 核心指标卡 + 近 30 天注册、记账、收支趋势图 |
| A3 | 用户管理 | 用户列表、搜索、筛选、查看单个用户详情 |
| A4 | 账单流水 | 跨用户筛选账单，按条件汇总金额 |
| A5 | 统计报表 | 按年或近 12 个月查看收支统计 |
| A6 | 数据导出 | 用户列表、账单流水导出为 CSV 文件 |

#### A2 数据总览

展示四项核心指标：累计用户数、账单总数、累计支出、累计收入，以及结余（收入减支出）。同时显示近 30 天的登录活跃人数、记账活跃人数，以及每日注册数、每日记账笔数、每日收支的折线/柱状趋势图。

#### A3 用户管理

列出所有注册用户，支持按用户名搜索、按条件筛选。点击某个用户可以进入详情页，查看该用户的基本信息和记账概况。

#### A4 账单流水

面向所有用户，可按用户、类型（支出/收入）、日期范围等条件筛选账单，并汇总出筛选结果的总支出、总收入。适合运营人员做整体账务核对。

#### A5 统计报表

支持按「某一年」或「近 12 个月」两个口径查看收支统计，用图表展示月度收支变化。

#### A6 数据导出

用户列表和账单流水都支持导出为 CSV 文件，导出的数据受当前筛选条件约束，单次导出上限 10 万条。CSV 文件可直接用 Excel 打开。

## 五、操作说明

### 5.1 新用户第一次使用（Web 端）

1. 浏览器打开产品地址，自动进入登录页。
2. 点「没有账号？立即注册」，进入注册页。
3. 设置用户名和密码（密码需 6 位以上，四类字符里至少三类），确认后注册。
4. 注册成功会自动登录，直接进入「记一笔」页面。
5. 先到「我的 → 分类管理」添加几个常用分类（支出如餐饮、交通，收入如工资），再到「我的 → 账户管理」添加支付账户（如现金、支付宝）。
6. 回到「记一笔」，选分类、输金额、保存，第一笔账就记完了。

### 5.2 日常记账（App 端）

1. 打开 App，登录后默认停在「记一笔」页。
2. 默认是「支出」，点顶部可切到「收入」。
3. 点分类九宫格里的图标选择分类。
4. 用金额键盘输入金额。
5. 选账户、填备注（可不填）、确认日期。
6. 点保存，记账完成。

### 5.3 查看流水

1. 点底部「流水」或 Web 端进入「流水」页。
2. 列表按日期展示所有账单，支出为深灰色「-」、收入为薄荷绿「+」。
3. 点某一条账单，弹出详情，可在此编辑或删除该笔账。

### 5.4 查看年度统计

1. 点底部「统计」或 Web 端进入「年度统计」页。
2. 顶部可切换年份。
3. 依次查看记账概况、分类占比、收支趋势、分类排行。

### 5.5 退出登录 / 注销账号

1. 进入「我的」或「设置」。
2. 点「退出登录」，确认后结束本机登录，回到登录页，数据不受影响。
3. 点「注销账号」，会弹出警告，确认并输入密码后，该账号所有数据被永久清空，不可恢复。

### 5.6 运营管理员操作

1. 浏览器打开后台地址，自动进入管理员登录页。
2. 输入管理员账号密码登录（账号由部署时预置，见运维说明）。
3. 登录后默认进入「数据总览」，查看整体指标和趋势。
4. 左侧导航切换到「用户管理」，搜索或点开用户查看详情。
5. 切换到「账单流水」，设置筛选条件查看并汇总账单。
6. 切换到「统计报表」，按年或近 12 个月查看收支。
7. 在「用户管理」或「账单流水」页点「导出」，下载 CSV 报表。

## 六、技术架构说明

> 这一节面向运维和交付人员，普通用户可以不看。

### 1. 整体架构

产品是「前后端分离、同源部署」的结构，共三个前端加两个后端，共用同一个 MySQL 数据库。

```
┌─────────────┐   ┌─────────────┐   ┌─────────────┐
│  Web 网页端  │   │  移动端 App  │   │  运营后台    │
│ (静态 HTML) │   │  (uniapp)   │   │ (静态 HTML) │
└──────┬──────┘   └──────┬──────┘   └──────┬──────┘
       │      /api/*      │                │   /api/admin/*
       ▼                  ▼                ▼
┌──────────────┐                 ┌──────────────────┐
│  用户后端     │                 │  后台管理后端     │
│  (Express 5) │                 │  (Express 5)     │
│  端口 3000    │                 │  端口 3002        │
└──────┬───────┘                 └────────┬─────────┘
       │                                  │
       └──────────────┬───────────────────┘
                      ▼
            ┌─────────────────┐
            │  MySQL 8.0      │
            │ financial_steward│
            └─────────────────┘
```

- **Web 网页端**：零框架的静态 HTML + Tailwind CSS，由用户后端同源托管，前端通过 `/api/*` 调用后端。
- **移动端 App**：基于 uniapp（Vue 3）开发，一套代码支持 H5、微信小程序、Android、iOS、鸿蒙；通过 `/api/*` 调用同一个用户后端，数据与 Web 端互通。
- **运营后台**：静态 HTML + 本地 Chart.js 图表，由后台后端同源托管，通过 `/api/admin/*` 调用后台后端。
- **两个后端**：都是 Express 5 + mysql2，ESM 模块、无构建步骤，`npm start` 即可运行（带 nodemon 热重载）。

### 2. 数据库

数据库名为 `financial_steward`，共 9 张表，主要包含：

- `user`：记账用户账号（用户名、密码哈希、头像、注册时间等）；
- `bill`：账单（金额、类型、分类、账户、日期等）；
- `category`：分类；
- `account`：支付账户（仅标记，无余额）；
- `user_session`：用户会话；
- `admin_user`：超级管理员账号（账号与会话合一，与用户表完全隔离）。

一个关键约定：**金额一律以「分」为单位的整数存储和计算，全程不使用浮点数**。比如 12.34 元存成 1234。这样能避免浮点误差，保证账目精确。展示时再由前端换算成「元」。

### 3. 会话与安全

- 登录成功后，服务端在 Cookie 里存一个会话令牌，数据库里只存令牌的 SHA-256 哈希，不存明文。
- 会话默认 30 天，期间有活动会自动续期（滑动续期）。
- 页面有服务端守卫：未登录访问受限页面会自动 302 跳回登录页；App 端有等价的客户端守卫。
- 登录密码连续错 5 次锁定 10 分钟；密码以 bcrypt 哈希存储，不存明文。

### 4. 部署要点

| 服务 | 目录 | 启动命令 | 端口 |
|---|---|---|---|
| 用户后端（含 Web 端） | `003.前端代码/backend` | `npm start` | 3000 |
| 运营后台后端（含后台页面） | `005.后台管理系统(运营专员)/backend` | `npm start` | 3002 |

- 两个后端都依赖环境变量文件 `.env`，里面配置数据库连接等；参考同目录下的 `.env.example` 填写。
- 运营后台的超级管理员账号需要先预置：在后台后端目录执行 `npm run seed:admin`，会读取 `.env` 里的管理员用户名和密码，已存在则跳过。
- App 端连接后端时，H5 走开发代理，小程序/真机需要把接口地址改成运行后端那台电脑的局域网 IP（见 `006.跨端APP应用(移动端开发工程师)/uniapp-project/common/config.js` 里的说明），真机须与电脑连同一 Wi-Fi。

## 七、常见问题

**1. 注册后为什么分类和账户是空的？**
这是设计如此。新账号不会预置模板数据，需要用户先到「我的 → 分类管理」「我的 → 账户管理」里添加自己常用的分类和账户，之后记账就能直接选了。

**2. 登录提示密码错误，输对也登不上？**
密码连续输错 5 次会锁定 10 分钟，这是防暴力破解的机制。等 10 分钟后再试即可。

**3. 密码要满足什么要求？**
6 位以上，并且数字、小写字母、大写字母、特殊字符这四类里至少包含三类。

**4. 忘记密码怎么办？**
在登录页点「忘记密码」，输入账号后直接重设新密码，不需要验证码。

**5. 金额会算错吗？**
不会。系统内部金额全部用「分」的整数存储和计算，不用浮点数，不会有几分钱的误差。

**6. 账户里的「余额」在哪里看？**
没有余额。这里的「账户」只是支付方式的标记（现金、支付宝、微信等），不是银行卡余额体系，这是产品刻意做的减法。

**7. 分类名称能起多长？**
最多 6 个汉字。

**8. 记一笔的分类太多了怎么办？**
分类九宫格每页显示 6 个，超过会自动分页，左右翻页即可找到。

**9. 退出登录会丢数据吗？**
不会。退出只是结束本机登录，数据都存在服务器上，重新登录后都在。

**10. 注销账号和退出登录有什么区别？**
退出登录是可逆的，随时能再登录回来。注销账号是永久性的，会清空该账号全部记账数据，且不可恢复，操作前会要求输入密码确认。

**11. Web 端和 App 的数据是同一份吗？**
是的。两者连同一个后端、同一个数据库，用同一个账号登录，看到和记录的是同一份账。

**12. 运营后台能修改用户的账吗？**
不能。运营后台全部只读，只能查看、统计和导出，不能改动任何用户数据。

**13. 运营后台的账号从哪里来？**
由运维人员在部署时用 `npm run seed:admin` 预置，账号密码写在 `.env` 里，与用户端账号完全隔离。

**14. 导出的 CSV 用 Excel 打开乱码怎么办？**
导出的 CSV 已带 UTF-8 BOM，正常用 Excel 直接打开不会乱码。如果仍异常，可在 Excel 里用「数据 → 从文本/CSV」导入并选择 UTF-8 编码。

**15. App 连不上后端怎么办？**
真机调试时，App 的接口地址需要改成运行后端那台电脑的局域网 IP，并保证手机和电脑连的是同一个 Wi-Fi。改网络后 IP 会变，需同步更新 `common/config.js` 里的地址。
