## 1. 产品概述

### 1.1 一句话定位

**给超级管理员（运营负责人）用的数据查看台**——用专属账号登录后台，一眼看清注册了多少用户、他们记了多少账、钱花在哪、从哪来，随时可下钻到单个用户核对数据。

### 1.2 背景与问题

- 用户端「财务管家」已上线 F1–F7（注册登录、记一笔、流水、年度统计），数据全部落在 `financial_steward` 库。
- 目前**没有任何手段查看全局运营数据**：有多少注册用户、日活/留存如何、整体记账规模多大、支出/收入结构如何，只能靠人工查库。
- 需要一个**独立于用户端的运营后台**，把这些数据可视化成可直接阅读的列表与统计，供超级管理员日常查看与核对。

### 1.3 目标用户

| 画像 | 特征 | 核心诉求 |
|---|---|---|
| 超级管理员（运营负责人） | 掌握产品整体运营数据，需按天/周看用户增长与记账活跃，核对异常数据 | 用专属账号登录后台，看总览、查用户与账单 |
| 产品/负责人 | 阶段性复盘产品数据 | 看注册趋势、活跃、收支结构 |

### 1.4 目标与成功指标

| 目标 | 指标 | V1 目标值 |
|---|---|---|
| 数据可读 | 核心指标首屏 ≤ 1 次点击可查 | 100% |
| 查询效率 | 按用户名查到用户及账单 | ≤ 3 步 |
| 数据准确 | 后台数字与逐笔求和一致（金额以分整数运算） | 100% |

### 1.5 边界声明（重要）

- 后台管理系统是**运营侧数据查看工具**，与用户端是两套独立的前后端、独立登录体系；**超级管理员账号与普通用户账号分表存储、互不混用**，且不改动用户端产品与数据口径。
- V1 定位为**只读为主**：以「查看用户、查看账单、查看统计」为核心；对用户的封禁、注销等管理操作列为可选（P1），默认不做数据写入。
- 后台**不具备会计/税务效力**，不替代财务软件；金额展示与用户端一致（元、两位小数）。

## 2. 版本范围

### 2.1 V1.0 范围内（本 PRD 详述）

1. 超级管理员登录与鉴权（独立账号，全系统仅新增一张表）

3. 用户管理（列表、搜索、筛选、用户详情下钻）
4. 账单流水查看（跨用户，支持按用户/时间/类型筛选）
5. 统计报表（收支趋势、分类占比、账户分布）
6. 数据导出（用户列表 / 账单 CSV，P1 可选）

### 2.2 V1.0 范围外（明确不做，防止蔓延）

| 功能 | 处理 |
|---|---|
| 修改用户密码 / 重置密码 | 不做（涉及用户端账号安全，后续评估） |

| 埋点/留存分析平台、自定义报表 | 不做（远期候选池） |
| 多管理员账号 / 多角色分级 | V1 仅「超级管理员」单一账号体系，不做角色分级；多账号/分级留后续 |
| 移动端适配 | 不做（桌面优先） |

## 3. 功能需求

> 需求编号规则：A{序号}；优先级：P0 = V1 必须交付，P1 = 应交付（可选）。

### 3.1 A1 超级管理员登录与鉴权（P0）

**描述**：超级管理员用自己的账号密码登录后台，未登录一律跳登录页。**账号与用户端普通用户完全隔离、分表存储、互不混用**，且**整个后台系统仅新增一张表**承载超级管理员账号与会话。

**业务规则**：

1. **独立超级管理员账号（全系统仅一张新表）**：新增 `admin_user` 表，账号与会话字段合一；与用户端 `user` 表**完全隔离、互不混用**（普通用户与超级管理员分属两表，登录互不通行）。超级管理员账号由开发**预置**（种子脚本/环境变量），V1 **不开放自助注册**。
2. 密码只存哈希 + 盐（bcrypt/argon2 级别），与用户端同强度要求；禁止明文或可逆加密。
3. **登录**：用户名 + 密码，登录失败统一提示「用户名或密码错误」（不泄露账号存在性）；连续错 ≥ 5 次锁定 10 分钟（沿用用户端 F1-3 策略）。
4. **会话（复用单表，不另建会话表）**：登录令牌明文只存 Cookie（独立 Cookie 名 `fgj_admin_session`，与用户端 `fgj_session` 区分），库中在该 `admin_user` 行的 `token_hash` 存 SHA-256 哈希 + `token_expires_at` 记过期时间；同一账号仅保留一个有效会话（后登录覆盖先登录），有效期 30 天滑动续期。
5. **登录守卫**：后台所有页面与 `/api/admin/*` 接口未带有效超级管理员会话一律 302 回登录页（页面）/ 401（接口）。
6. **登出**：清空该行 `token_hash` / `token_expires_at` 并清除 Cookie，回登录页。

**验收标准**：

| # | 验收项 | 标准 |
|---|---|---|
| 1 | 登录 | 正确账号密码进入后台首页；错误统一提示 |
| 2 | 隔离 | 超级管理员与普通用户分属两表：普通用户无法登录后台，超级管理员无法登录用户端 |
| 3 | 守卫 | 未登录直接访问任意后台页/接口被重定向或 401 |
| 4 | 锁定 | 连错 5 次锁定 10 分钟，期间正确密码也拒绝 |
| 5 | 单表约束 | 后台仅新增 `admin_user` 一张表，不新增 `admin_session` 等任何其他表 |

### 3.2 A2 数据总览仪表盘（P0）

**描述**：登录后的默认首页，一张屏看清全局经营状况。

**业务规则**：

1. **核心指标卡**（顶部，固定一排）：累计注册用户数、累计账单笔数、累计支出合计、累计收入合计、累计结余（收入−支出）。
2. **活跃口径**：近 30 天有登录的用户数（`user.last_login_at`）、近 30 天有记账的用户数（`bill` 去重 `user_id`）。
3. **趋势图**（P0 基础版）：
   - 新增注册趋势（按日，近 30 天；按日累计注册数，近 30 天）；
   - 记账活跃趋势（按日账单笔数，近 30 天）；
   - 收支趋势（按日支出/收入合计，近 30 天）。
4. 金额一律以「分」整数运算后展示为「元、两位小数」，全程无浮点。
5. 各卡片点击可跳转到对应明细列表（如「累计用户」→ 用户列表，「支出合计」→ 账单列表）。

**验收标准**：

| # | 验收项 | 标准 |
|---|---|---|
| 1 | 指标准确 | 各指标与全表聚合一致（金额分整数求和） |
| 2 | 趋势 | 近 30 天按日补齐（无数据日为 0），曲线正确 |
| 3 | 下钻 | 指标卡可跳转对应明细页 |

### 3.3 A3 用户管理（P0）

**描述**：查看所有注册用户，支持搜索/筛选，点击进用户详情。

**业务规则**：

1. **用户列表**（分页，默认每页 20 条）：列含 UID、用户名、头像、账号状态、注册时间、最后登录时间、账单笔数、累计支出/收入（聚合）。
2. **搜索**：按用户名（模糊、不区分大小写）或 UID 精确搜索。
3. **筛选**：账号状态（active / deleting / deleted）、注册时间范围、有无账单（≥1 笔 / 0 笔）。
4. **排序**：按注册时间、最后登录、账单笔数、支出额等列排序。
5. **状态展示**：active 正常、deleting 注销冷静期（展示到期时间）、deleted 已注销墓碑。
6. **用户详情（下钻）**：
   - 基本信息：用户名、UID、头像、注册时间、最后登录、状态、已坚持天数（沿用用户端口径）；
   - 收支汇总：累计支出/收入/结余、账单总笔数、记账天数（去重日期）；
   - 分类统计：该用户支出/收入分类排行（金额 + 笔数）；
   - 账户统计：该用户支付方式使用分布（按账单 account_id 聚合）；
   - 最近账单：该用户最近 N 笔流水。
7. 详情页提供「查看该用户全部账单」入口，跳转到账单列表并自动带上该用户筛选。

**验收标准**：

| # | 验收项 | 标准 |
|---|---|---|
| 1 | 列表准确 | 列表字段与库一致，聚合金额分整数求和 |
| 2 | 搜索筛选 | 按用户名/UID/状态/时间范围正确过滤 |
| 3 | 详情完整 | 用户详情各区块数据正确，分类/账户聚合与账单一致 |
| 4 | 下钻 | 从详情一键查看该用户全部账单 |

### 3.4 A4 账单流水查看（P0）

**描述**：跨用户查看全部账单流水，支持多条件筛选，供核对数据。

**业务规则**：

1. **账单列表**（分页）：列含账单 ID、用户名（可点进用户详情）、类型（支出/收入）、金额、分类、账户、备注、记账日期、记录时间。
2. **筛选**：按用户（用户名/UID）、时间范围（按 `bill_date`）、类型（支出/收入）、分类、账户。
3. **排序**：按记账日期、记录时间、金额倒序等。
4. **金额语义色**：支出深灰带「-」、收入薄荷绿带「+」（沿用用户端 6.5 语义色）。
5. 列表可汇总当前筛选条件下的支出合计、收入合计、笔数。
6. 单条可展开查看详情（全部字段，含记录时间、备注；未填显示「—」）。

**验收标准**：

| # | 验收项 | 标准 |
|---|---|---|
| 1 | 列表与筛选 | 各筛选条件组合正确，分页正确 |
| 2 | 汇总 | 当前筛选下支出/收入/笔数与逐笔求和一致 |
| 3 | 详情 | 展开详情字段完整、准确 |

### 3.5 A5 统计报表（P0）

**描述**：全局维度的收支结构与趋势分析。

**业务规则**：

1. **时间维度切换**：按年/按月切换（至少支持「最近 12 个月」「按年」）。
2. **收支趋势**：所选时间范围内支出/收入合计趋势（按日或按月）。
3. **分类排行**：全局支出分类占比/排行、收入分类占比/排行（金额 + 笔数 + 占比），复用用户端 F7 的口径与排序规则。
4. **账户（支付方式）分布**：全局账单按支付方式聚合的金额与笔数。
5. 金额分整数运算，占比计算与用户端 F7 一致。

**验收标准**：

| # | 验收项 | 标准 |
|---|---|---|
| 1 | 口径一致 | 全局分类/账户聚合与逐笔求和一致 |
| 2 | 时间切换 | 切换时间维度后各板块同步刷新 |

### 3.6 A6 数据导出（P1，可选）

**描述**：将用户列表、账单流水导出为 CSV/Excel，供运营离线分析。

**业务规则**：

1. 导出「当前筛选结果」的用户列表 / 账单列表，受同一筛选条件约束。
2. 导出字段与列表展示字段一致；金额导出为「元、两位小数」。
3. 单次导出条数设上限（如 10 万条），超限提示缩小筛选范围。

**验收标准**：导出文件可打开、字段与筛选结果一致、金额格式正确。

### 3.7 A7 用户管理操作（P1，可选，默认只读）

> 如运营需要干预能力，按以下优先级逐步放开；V1 默认**只读不做写入**。

| 操作 | 说明 | 优先级 |
|---|---|---|
| 查看 | 用户/账单/统计全量查看 | P0 |
| 封禁/解封用户 | 新增 `user.status` 枚举或 `banned_at` 字段，封禁后禁止登录 | P1 |
| 手动注销用户 | 直接置 `deleting`（冷静期）或 `deleted` | P1 |
| 操作审计 | 记录管理员操作日志（谁、何时、对哪个用户、做了什么） | P1（一旦有写入即必须） |

> 说明：封禁、注销、审计涉及对用户端 `user` 表与登录逻辑的改动，需与用户端 PRD 同步评审，不属于本后台独立可交付范围，故列为 P1 并默认不实现。

## 4. 数据与依赖

### 4.1 复用的数据表（只读）

| 表 | 用途 |
|---|---|
| `user` | 用户列表、注册趋势、活跃（last_login_at）、状态、用户详情基本信息 |
| `bill` | 账单流水、收支合计、分类/账户聚合、趋势（核心表） |
| `category` | 分类名称/图标，账单 JOIN 取分类 |
| `account` | 账户（支付方式）名称，账单 JOIN 取账户 |
| `user_session` | （可选）在线会话数 / 活跃会话统计 |

### 4.2 新增的表（全系统仅此一张）

| 表 | 字段要点 | 说明 |
|---|---|---|
| `admin_user` | id, username(唯一), password_hash, token_hash(可空), token_expires_at(可空), failed_login_count, locked_until(可空), last_login_at(可空), created_at, updated_at | 超级管理员账号与会话**合一**：账号由开发预置、不开放注册；登录令牌明文只存 Cookie，库中仅存 SHA-256 哈希；与 `user` 表完全隔离 |

> **单表硬约束**：后台管理系统**仅新增 `admin_user` 这一张表**（与用户端同库 `financial_steward`）；其余 `user`/`bill`/`category`/`account` 等一律只读复用，不新增也不改动。若未来实现 A7 写入操作，另需 `admin_audit_log`（审计日志）与 `user` 封禁字段，届时**再单独评审**，不属当前 V1 单表约束。

### 4.3 金额与时间口径（硬约定）

- 金额一律以「分」为单位的整数存储与计算，全程禁用浮点（与用户端一致）；仅在展示层换算为「元、两位小数」。
- 时间范围筛选按 `bill_date`（记账日期）与 `created_at`（记录时间）区分使用：流水按 `bill_date` 归集，活跃按 `created_at`/`last_login_at`。

## 5. 非功能需求

| 类别 | 要求 |
|---|---|
| 权限 | 后台接口一律超级管理员会话鉴权（`admin_user` 表）；数据读 `financial_steward` 库，独立于用户端鉴权（`fgj_session`） |
| 安全 | 管理员密码哈希 + 盐；登录失败锁定；全站 HTTPS；后台不对外暴露用户端会话 |
| 性能 | 列表分页、聚合查询走索引（`idx_bill_user_date_created` 等）；核心接口 P95 ≤ 500ms；大数据量下趋势图按需聚合 |
| 兼容 | 桌面浏览器优先（Chrome/Edge/Safari 最新版），视口 ≥ 1024px |
| 可用性 | 只读后台不写入业务数据，误操作风险低；导出操作有进度/超限提示 |
| 审计 | 若开放写入操作（A7），必须记录操作日志（谁、何时、对谁、做了什么） |

## 6. 页面与信息架构

```
登录页（未登录）
└─ 管理后台（登录后）
   ├─ [仪表盘] 数据总览（默认首页，A2）
   ├─ [用户]   用户列表 → 用户详情（A3）
   │                └─ 该用户全部账单（跳 A4 带筛选）
   ├─ [账单]   账单流水查看（A4）
   └─ [统计]   统计报表（A5）
```

**视觉基调**：延续「财务管家」品牌（樱花粉主色 `#FF8FAB`），但采用**后台桌面布局**（左侧导航 + 顶部栏 + 内容区表格/卡片），区别于用户端移动优先；金额沿用语义色（支出深灰「-」、收入薄荷绿「+」）。

## 7. 风险与依赖

| 风险/依赖 | 影响 | 应对 |
|---|---|---|
| 超级管理员账号泄露 | 后台可看全量用户数据 | 密码哈希、登录锁定、建议独立部署与 IP 白名单 |
| 只读与写入边界模糊 | 需求蔓延到「管理用户」，超出查看初衷 | 以 2.2 范围外清单为锚，写入操作一律走 A7 单独评审 |
| 大数据量下聚合变慢 | 趋势/分类聚合慢 | 复用 bill 索引，趋势按日聚合；必要时加汇总表（后续） |
| 与用户端口径不一致 | 后台数字与用户端对不上 | 金额分整数、占比口径复用用户端 F7 规则，联调核对 |
