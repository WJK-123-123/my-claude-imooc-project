## 1. 产品概述

### 1.1 一句话定位

**财务管家是一个点开就能记、记完就能走的极简记账网页工具**——不用下载 App，一个账号密码随时登录，3 步记完每一笔，按月看清收支结余。

### 1.2 背景与机会

- **记账工具普遍过重**：主流记账产品（随手记、鲨鱼记账、钱迹等）功能庞杂（预算、账单导入、理财导流），对"只想每天记一笔"的用户是负担。
- **下载门槛真实存在**：临时性、尝鲜性用户不愿为"记个账"安装一个 App；Web 端点开链接即用，是天然的轻量入口。
- **小微个体户存在空白**：他们记的是"进货、日营业款"这类流水，专业财务软件用不懂，Excel 太麻烦，需要一个够简单、手机上随手能记的工具。
- **核心洞察**：记账产品的成败不在功能多，而在**记得住（习惯）**。每天记录消费的场景里，"快"就是最大的价值。

### 1.3 产品命名（已定名）

**定名：财务管家**——直白传达"帮你打理收支的贴心管家"，认知零成本；与粉嫩可爱的视觉风格（见 6.5）天然契合，后续可延伸「小管家」IP 形象用于空状态插画与品牌传播。

| 历史候选 | 说明 | 结果 |
|---|---|---|
| 轻账 | "轻"传达极简无负担，"账"直指领域 | 已否决 |
| 一笔记 | 双关：一笔记完 / 记一笔账，传达速度感 | 已否决 |
| 简账 | 直白表达"简单的账本" | 已否决 |

### 1.4 产品目标与成功指标（V1）

| 目标 | 指标 | V1 目标值（基线，待运营校准） |
|---|---|---|
| 新用户快速上手 | 登录成功后 24h 内记完首笔的转化率 | ≥ 80% |
| 记账习惯形成 | 次日留存 / 7 日留存 | ≥ 40% / ≥ 25% |
| 产品核心价值 | 活跃用户人均日记账笔数 | ≥ 1.5 笔 |
| 体验效率 | 「记一笔」操作耗时（中位数） | ≤ 8 秒 |

### 1.5 产品定位声明（重要边界）

- 财务管家是**个人/小微商户的收支流水记录工具**，不是财务软件、会计软件或税务工具，账单数据不具备会计凭证效力。
- V1 面向 18 岁以上用户，未成年人不作为目标用户。

## 2. 目标用户与使用场景

### 2.1 用户画像

| 画像 | 代表 | 特征 | 核心诉求 |
|---|---|---|---|
| P1 都市个人 | 小林，27，上班族 | 每天线上线下消费多笔，想知道钱花哪了；嫌记账 App 臃肿、要下载 | 付款后 10 秒内记完，月底看流水 |
| P2 家庭/情侣记账人 | 阿哲，30，同居中 | 家庭消费主要由一人统筹记录 | 一处记全家的收支，按月看结余 |
| P3 小微个体户 | 强哥，38，面馆/网店店主 | 进货、日营业款想简单记下来；不会用财务软件 | 记生意流水，月底知道挣了多少 |

### 2.2 核心用户故事

- 作为一个上班族，**我想在付款后顺手 10 秒内记完一笔支出**，以便不打断正在做的事。
- 作为家庭记账人，**我想按月查看家庭收支与结余**，以便掌握家庭财务状况。
- 作为一个个体户，**我想分别记录每天的进货支出和营业收款**，以便月底算清利润。
- 作为一个新用户，**我不想填一堆资料注册**，设置一个用户名密码就能快速开始，数据不会因为换设备而丢失。

### 2.3 场景判断（V1 明确取舍）

- **家庭/情侣**：V1 为单账号单人使用，由"主要记账人"记录家庭整体收支；多人共享账本列入 V2（见版本规划），避免 MVP 膨胀。
- **个体户**：自行添加生活与生意类目（附录 A 生活账/生意账清单可作参考）+ 备注满足记账需求；发票、报销、库存等明确不做（见范围外清单）。

## 3. 版本规划

### 3.1 V1.0 范围内（本 PRD 详述）

1. 用户名密码登录与注册（分页）、找回密码、登出、注销账号

## 4. 功能需求

> 需求编号规则：F{序号}；优先级：P0 = V1 必须交付，P1 = 应交付。

### 4.1 F1 账号：用户名密码登录 / 注册 / 找回密码（P0）

**描述**：登录与注册分页。注册设置用户名与密码后自动登录；登录校验用户名与密码；忘记密码时通过验证码验证身份后重置。数据云端保存，换设备用同一账号登录不丢数据。

**业务规则**：

1. 用户名 2–20 个字符，支持中文、字母、数字、下划线；查重不区分大小写（`XiaoLin` 与 `xiaolin` 视为同一用户名）。
2. 密码 6–20 位，支持任意可见字符（不含空格），且需包含数字、小写字母、大写字母、特殊字符四类中的至少三类；不符合规范时提示「密码不符合规范，请重新输入」；输入框密文显示（type=password）。
3. **登录页**：用户名 + 密码 + 协议勾选；常驻「没有账号？去注册」引导与「忘记密码？」入口。登录失败统一提示「用户名或密码错误」，不区分具体原因（不泄露用户名是否已注册，防撞库）；同一用户名连续密码错误 ≥ 5 次锁定 10 分钟。
4. **注册页**：用户名 + 密码 + 确认密码（两次输入须一致）+ 协议勾选；用户名已占用时明确提示「用户名已被占用」；注册成功自动登录并直接进入主界面（记账页），新账号分类与支付方式账户**初始为空**，由用户自行添加（见 F2 变更说明）。
5. **找回密码页**：输入用户名 → 获取 6 位验证码（发送后 60s 倒计时；验证码错误 ≥ 5 次作废需重新获取）→ 验证通过进入设置新密码 → 重置成功跳回登录页，旧密码立即失效。正式版验证码经短信/邮箱发送；用户名不存在时提示「用户名不存在」。
6. 密码只存哈希 + 盐（bcrypt/argon2 级别），禁止明文或可逆加密的存储与传输。
7. 登录态有效期 30 天（滑动续期）；过期后访问需重新登录。
8. 登出：清除本地登录态，回到登录页；云端数据不受影响。
9. 注销账号：「我的」页入口，需二次确认 + 输入登录密码校验；提交后进入 7 天冷静期，期间登录可撤销注销；期满后账号与全部账单数据不可恢复地删除。

**验收标准**：

| # | 验收项 | 标准 |
|---|---|---|
| 1 | 新用户注册 | 未占用用户名 + 两次一致密码 → 建号、自动登录并直接进入记账页，分类与支付方式账户初始为空 |
| 2 | 占用拦截 | 已占用用户名注册时提示「用户名已被占用」 |
| 3 | 老用户登录 | 已注册用户名 + 正确密码 → 直接进入记账页，历史数据完整 |
| 4 | 登录错误提示 | 统一提示「用户名或密码错误」，不泄露用户名存在性 |
| 5 | 锁定保护 | 连续错 5 次锁定 10 分钟，期间即使密码正确也拒绝登录 |
| 6 | 找回密码 | 验证码验证通过后设置新密码；新密码立即可登录，旧密码失效 |
| 7 | 协议拦截 | 未勾选协议时无法登录/注册，有明确提示 |
| 8 | 登录态 | 30 天内再次打开免登录；登出后需重新登录 |
| 9 | 注销 | 需密码确认；冷静期内可撤销；期满后数据删除且无法再以原用户名查到任何账单 |

### 4.2 F2 首次场景引导（已移除，V1.6）

> **V1.6 砍掉**：注册成功自动登录后**直接进入主界面（记账页）**，不再有引导屏。**V1.9 起**新账号分类与支付方式账户**初始为空**，不再按附录 A 模板初始化，由用户通过分类管理/账户管理页自行添加（附录 A 生活账/生意账清单转为自定义参考）。原业务规则与验收标准全部作废；编号 F2 保留不复用，F3–F7 引用不受影响。

### 4.3 F3 记一笔（P0，核心功能）

**描述**：产品核心页面。大数字键盘 + 分类九宫格，3 步内完成：选分类 → 输金额 → 点保存。

**业务规则**：

1. **金额**：必填；自定义大数字键盘（0-9、小数点、退格、保存键）；最多两位小数；上限 999,999.99；整数态下小数点后自动补「.00」输入体验（输 12 → 显示 12，输小数点后进入角分输入）。金额未输入时点保存 → 抖动提示「请输入金额」。
2. **类型**：页面顶部「支出 / 收入」分段切换，默认支出；切换后分类区联动为对应类型下的分类，金额不清空。
3. **分类**：九宫格展示（每页 8 个 + 1 个「+」新增格），可左右翻页；选中态高亮。默认选中第一个分类；无分类时显示空状态引导。
4. **新增自定义分类**：点击「+」格 → 弹层输入名称（≤4 个汉字，查重）→ 选择图标（内置 emoji 图标库 24 个）→ 选择归属（跟随当前支出/收入类型）→ 保存后立即出现在九宫格。V1 不支持编辑、删除、排序。
5. **备注**：可选，≤50 字，输入框单行，占位文案用引导式提问（「这笔钱花在哪里了？」），降低输入心理门槛。
6. **日期**：默认今天；点击可改，可选范围 2000-01-01 至今天；跨月/跨年可选。
7. **保存**：点击保存 → 按钮 loading → 成功 toast「已记一笔 ✓」（1.5s）→ 表单自动重置（保留类型与上一次分类），停留在记账页支持连续记账。保存失败（弱网）→ 提示重试，已填内容不丢失。
8. **入口**：底部导航中央大按钮「+」；记账页为登录后的默认落地页。
9. **支付方式**：选填标记字段，胶囊 chips 展示用户账户列表（初始为空，到账户管理页添加）；再点一次取消选中；未选不影响保存。仅为账单标记（F5 详情展示），不构成账户体系（多账户余额管理见 3.2 范围外），也不增加记账必选步骤。

**验收标准**：

| # | 验收项 | 标准 |
|---|---|---|
| 1 | 记账效率 | 熟练用户 3 步（选分类/输金额/保存）完成，≤8 秒 |
| 2 | 金额校验 | 非空、≤2 位小数、≤999,999.99，非法输入被键盘直接拦截 |
| 3 | 类型联动 | 支出/收入切换后分类区正确联动，金额保留 |
| 4 | 自定义分类 | 新增后立即可用并可用于记账；名称查重 |
| 5 | 日期规则 | 默认今天；不可选未来日期 |
| 6 | 保存反馈 | 成功 toast + 表单重置；失败不丢数据 |
| 7 | 连续记账 | 保存后无需返回，可直接记下一笔 |
| 8 | 支付方式 | 选填、可取消；未选不影响保存与「3 步记账」效率 |

### 4.4 F4 流水列表（P0）

**描述**：按月组织的账单流水，回答"这个月花了多少、挣了多少"。

**业务规则**：

1. **月份切换**：顶部「← 2026年10月 →」选择器，左右切换相邻月；提供「回到本月」快捷入口；最早可浏览到有账单的月份。
2. **月小结卡**：固定在列表顶部——本月支出合计、本月收入合计、本月结余（收入−支出）；金额保留两位小数。
3. **按日分组倒序**：日期组头显示「10月17日 星期六 · 支出 86.00 · 收入 0.00」；组内账单按创建时间倒序。单条展示：分类图标 + 分类名 + 备注摘要（超长截断）｜金额：支出「-86.00」深灰，收入「+320.00」薄荷绿（语义色定义见 6.5）。
4. **点击单条** → 进入账单详情（见 F5）。
5. **空状态**：「本月还没有账单」+「去记一笔」按钮直达记账页。
6. **数据范围**：按月整月加载，不做跨月无限滚动；单月账单超过 100 条时分组折叠为日（默认仅展开最近 3 天）。

**验收标准**：

| # | 验收项 | 标准 |
|---|---|---|
| 1 | 月小结准确性 | 合计、结余与该月账单逐笔求和一致（金额以分为单位计算，避免浮点误差） |
| 2 | 分组排序 | 组间按日期倒序、组内按时间倒序 |
| 3 | 金额展示 | 支出带「-」深灰、收入带「+」薄荷绿（见 6.5 语义色） |
| 4 | 月份切换 | 切换后数据、小结同步刷新；「回到本月」一键返回 |
| 5 | 空状态 | 无账单月份显示引导，按钮可跳转记账页 |

### 4.5 F5 账单详情 / 编辑 / 删除（P0）

**业务规则**：

1. **详情**：展示全部字段——类型、金额、分类、支付方式、备注、日期、记录时间；备注与支付方式未填显示「—」。
2. **编辑**：所有字段可改（金额键盘、分类九宫格、日期、备注复用记账页组件）；保存后详情与流水即时更新。
3. **删除**：底部「删除」珊瑚红入口（#FF6B6B，见 6.5）→ 二次确认弹窗「删除后不可恢复」→ 确认后删除并返回流水，月小结同步更新。

**验收标准**：

| # | 验收项 | 标准 |
|---|---|---|
| 1 | 编辑生效 | 修改任意字段保存后，流水列表与月小结同步正确 |
| 2 | 删除保护 | 必须二次确认；删除后流水、小结立即更新 |
| 3 | 数据一致 | 编辑/删除操作在刷新页面后仍然生效（已持久化） |

### 4.6 F6 用户协议与隐私政策（P0，合规）

**业务规则**：

1. 登录页、登录流程、「我的」页均可查看；静态页面，标注版本号与更新日期。
2. 隐私政策需明示：收集信息仅限用户名与记账数据（密码仅存哈希，平台无法获知明文）、用途、保存期限、用户权利（查询/注销）、不向第三方共享。
3. 注册页明示「本产品面向 18 岁以上用户」。

**验收标准**：登录流程与「我的」页均可完整阅读两份协议；未勾选无法登录/注册（与 F1 联动）。

### 4.7 F7 年度收支统计（P1）

**描述**：从底部导航「统计」进入的年度收支分析页，回答「这一年的钱主要花在哪、从哪来」。纯结构化展示（分类占比 + 排行 + 记账概况），多月份趋势对比留 V2.0。

**业务规则**：

1. **入口**：底部导航「统计」常驻入口。
2. **年份**：统计页右上年份药丸切换年份（2000 年～本年），各板块按所选年份聚合。
3. **年度概览**：支出合计、收入合计、结余，数字与全年流水逐笔求和一致。
4. **支出分类占比/排行**：按金额降序，每项含分类图标、名称、金额、占比横条与百分比（占比 = 分类金额 ÷ 当年支出合计，一位小数）；无支出时显示空提示。
5. **收入分类占比/排行**：同上（占比分母为当年收入合计）。
6. **记账概况**：本年记账笔数、月均支出、最大单笔支出（含分类名）。月均支出 = 当年支出 ÷ 已过月数（本年取当前月，历史年取整年 12 个月）。
7. **空状态**：该年无账单时显示空状态引导。

**验收标准**：

| # | 验收项 | 标准 |
|---|---|---|
| 1 | 数字一致 | 概览三项与全年流水逐笔求和完全一致 |
| 2 | 排名与占比 | 分类按金额降序；占比基于同类型合计，条长与占比成比例 |
| 3 | 年份联动 | 统计页年份切换后各板块与排名同步刷新 |
| 4 | 月均规则 | 本年按已过月数、历史年按整年 12 个月计算 |
| 5 | 空状态 | 无账单年份显示引导，不显示空白区块 |

| 类别 | 要求 |

### 6.5 视觉设计规范（粉嫩可爱风）

**设计关键词**：粉嫩 · 可爱 · 治愈 · 干净——让"记账"这件略带压力的事变得轻松。

**色彩系统**：

| 色彩 | 色值 | 用途 |
|---|---|---|
| 樱花粉（主色） | `#FF8FAB` | 品牌识别、主按钮、分类选中态、底部导航激活态 |
| 浅粉（背景色） | `#FFF4F7` | 页面底色，营造整体粉嫩基调 |
| 奶油白 | `#FFFBFC` | 卡片、弹层底色，与浅粉底形成层次 |
| 樱桃深粉 | `#E5547B` | 按钮按下态、强调文字 |
| 薄荷绿（收入） | `#35C3A1` | 收入金额「+」、正结余——与粉色对比清晰，传达"进账" |
| 深灰（支出/正文） | `#4A4A4A` | 支出金额「-」、正文；可爱风下支出不用刺眼正红，减少焦虑感 |
| 珊瑚红（警示） | `#FF6B6B` | 删除入口、错误提示——柔和警示，不用正红 |
| 辅助灰 | `#999999` | 次要信息、占位文字 |

- 主按钮可用渐变：`#FFB6C8 → #FF8FAB`（自上而下）。
- 语义色与 F4/F5 联动：支出深灰「-」、收入薄荷绿「+」、删除珊瑚红、正结余薄荷绿 / 负结余珊瑚红。

**形状与质感（可爱感的来源）**：

- 大圆角：卡片 16px、分类格 20px、弹层 20px、按钮胶囊形（高 48px / 圆角 24px）。
- 柔和粉调阴影：`0 4px 12px rgba(255,143,171,0.16)`，全站禁用硬阴影。
- 分类图标沿用 emoji（天然可爱），置于浅粉圆底上，选中态圆底转白并轻微放大；支付方式为胶囊 chips（微信/支付宝/现金/银行卡），选中态粉描边；空状态与品牌插画使用「小管家」IP 形象（戴领结的粉色小猫/小兔，手持小账本）。
- 个体户等生意场景 V1 不做单独换肤，保持品牌统一（换肤列入远期候选池）。

**字体**：系统默认字体，不引入艺术字；记账页金额数字 ≥ 40px 加粗，保证核心输入场景的可读性。

**动效（Q 弹但克制，不拖慢记账）**：

- 按钮/分类格按下缩放至 0.97 并加深为樱桃深粉，松开回弹（≤150ms）。
- 保存成功 toast「已记一笔 ✓」轻微弹跳一次；分类选中时弹跳确认。
- 总原则：单次动效 ≤ 300ms，任何动效不得阻塞连续记账。

**无障碍红线**：

- 浅粉背景上的正文一律用深灰/深粉，对比度 ≥ 4.5:1，禁止浅粉字配浅粉底。
- 收入/支出不单靠颜色区分，必须带「+/−」符号（与 F4 规则联动，兼顾色弱用户）。

## 7. 数据模型（简述，供技术评估）

| 表 | 核心字段 | 说明 |
|---|---|---|
| user | id, username(全局唯一，不区分大小写), password_hash, salt, status(active / deleting / deleted), created_at, last_login_at | 注销走状态机：deleting = 冷静期 7 天；密码仅存哈希 |
| category | id, user_id, scope(expense/income), name, icon, sort, is_system, created_at | 用户自有分类（注册不初始化，自行添加） |
| bill | id, user_id, type(expense/income), amount(**整数，单位：分**), category_id, pay_method(wechat/alipay/cash/card, 可空), note(≤50字), bill_date(date), created_at, updated_at | 金额用分存储，避免浮点误差；支付方式仅为标记字段 |

**关键约束**：

- 所有查询强制 user_id 过滤，杜绝横向越权。
- 分类被账单引用后不可物理删除（V1 分类本身也不支持删除，天然规避）。
