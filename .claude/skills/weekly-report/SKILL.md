# 周报生成

把 git 提交记录梳理成一份中文周报，保存到 `000.文档纪要/`。

## 执行步骤

### 1. 确定汇报周期

默认「本周」= 本周一 00:00 到当前时刻。先用当前日期推算出本周一的日期（`YYYY-MM-DD`）：

- 今天是 2026-10-22（周四）→ 本周一为 2026-10-19。
- 通用做法：取 `date +%u`（周一=1）反推，或直接问清用户要哪一周。

用户可能指定别的周期（上周、指定起止日期、指定作者），先按用户口径来；未指定则用本周。

### 2. 读取提交记录

优先读本地 git（最可靠）。在仓库根目录执行：

```bash
# 本周提交列表（含文件统计，便于判断工作量）
git log --since="YYYY-MM-DD 00:00" --until="YYYY-MM-DD 23:59" \
  --pretty=format:"%h|%ad|%an|%s" --date=short

# 每条提交涉及的文件（可选，用于展开工作内容）
git log --since="..." --until="..." --stat --oneline
```

- 若需读远程 GitHub：可用 `gh` CLI（`gh api repos/{owner}/{repo}/commits?since=...`）或 github MCP 的 `list_commits`，但仅当本地仓库缺失或用户明确要求时使用。
- 提交信息是本项目自带的中文语义化信息，其中 `F1–F7`、`A1–A6` 对应 PRD 功能编号，`V1.x` 是 PRD 版本号，归类时直接复用这些编号与措辞。

### 3. 汇总归类

- 把提交按「功能 / 模块」聚合（参照 `CLAUDE.md` 的阶段目录与功能编号 F1–F7、后台 A1–A6）。
- 每条工作点写成一句「做了什么」，保留提交信息里的关键名词（接口路径、页面名、表名、版本号）。
- 去掉纯机械性提交（如 Initial commit、目录重命名）或只在概述中一笔带过。
- 若提交信息不足以说清内容，用 `git show <hash> --stat` 或查看 `CLAUDE.md`/PRD 对应条目补充。

### 4. 生成周报文档

按以下模板写中文周报：

```markdown
# 财务管家 · 周报

> 汇报周期：YYYY-MM-DD ~ YYYY-MM-DD（第 N 周）
> 生成时间：YYYY-MM-DD
> 数据来源：git 提交记录

## 一、本周工作概述

（一段话，概括本周主线成果与推进方向）

## 二、本周工作明细

### 1. <模块 / 功能名>（<F编号 / A编号>）
- <工作点 1>
- <工作点 2>

### 2. ...
- ...

## 三、下周计划

- （根据本周未完成项与项目阶段，给出合理推断，标注为「计划」）

## 四、问题与风险

- （无则写「无」，有则如实列出）
```

### 5. 保存文件

- 目录：`000.文档纪要/`（不存在则创建）。
- 文件名：`周报-YYYY-MM-DD.md`，其中 `YYYY-MM-DD` 为汇报周期最后一天（本周则为周日）。示例：`周报-2026-10-25.md`。
- 同名文件已存在时：追加序号 `周报-2026-10-25-2.md`，不覆盖已有内容。

## 注意事项

- 周报面向个人/团队回顾，语言平实、以事实为准，不夸大不遗漏。
- 金额、数量等数据若有涉及，严格沿用提交记录中的真实口径，不得虚构。
- 全程中文输出。
